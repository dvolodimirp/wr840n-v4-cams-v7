# OpenWrt 24.10 для TL-WR840N v4: USB + дві USB-вебкамери + меню «Вебкамери» (v7: рушій ustreamer)

## Що нового у v5
- **Патч 040** (mjpg-streamer): при `select() timeout` або помилці захоплення стрім перезапускається на місці (до 3 спроб).
  Якщо не вдається, процес одразу завершується, і procd піднімає чистий екземпляр (`respawn 3600 5 0`: 5 с затримки, без ліміту спроб).
  Раніше вхід помирав, звільняв буфер, поки HTTP-вихід ще його читав, і виникав SIGSEGV.
- **Патч 050** (mjpg-streamer): YUYV -> JPEG напряму з YCbCr 4:2:0 (`raw_data_in`) + `JDCT_IFAST`, без пікселя-за-пікселем YUV->RGB.
  Бенчмарк без SIMD (як на MIPS): у 1.5-2.4 раза швидше, PSNR не гірший (352x288 q80: 2.83 -> 1.16 мс/кадр; 640x480: 6.7 -> 3.9 мс).
- За замовчуванням збирається `openwrt-24.10`.

## Збірка
1. Залийте вміст папки в репозиторій GitHub (разом з `.github/`).
2. Actions -> Build OpenWrt TL-WR840N v4 -> Run workflow, поле: `openwrt-24.10`.
3. Artifacts: `sysupgrade.bin`, `tftp-recovery.bin`, `SHA256SUMS`, `config.used`.
   У лозі останнього кроку видно розмір `sysupgrade` відносно ліміту 7808 КБ.
4. Крок «Patch mjpg-streamer» кладе патчі з `patches/mjpg-streamer/` у feed; якщо вони не лягають, збірка падає (пришліть лог).

## Рекомендації після прошивки
- Починайте з 352x288 @ 5 fps або 320x240 @ 10 fps, потім піднімайте по одному параметру й дивіться `top`.
- У логах `logread | grep mjpg` рядки `select() timeout` + `exiting for respawn` означають автоперезапуск.

## Меню
`files/usr/share/luci/menu.d` реєструє пункт меню «Вебкамери» (LuCI 24.10).
Старий варіант 19.07 (`config.19.07.seed`, `files/usr/lib/lua/...`) залишено лише для довідки.

## Відновлення після зависання USB
`cams-watchdog` (щохвилини): перший збій = перезапуск потоків; другий поспіль = `cams-usbreset` (повторна енумерація USB, як перепідключення) + перезапуск.
Те саме при завантаженні, якщо перші 2 спроби старту не дали кадрів.

## v6: нове
- **Поворот 180°** для кожної камери (меню «Вебкамери» -> «Поворот зображення»). Реалізовано в патчі 060 (`-swrot180`), без додаткового навантаження. 90° свідомо не реалізовано.
- **Діагностика fps**: якщо змінна оточення `MJPG_STATS=1`, mjpg-streamer раз на 5 с пише в лог, скільки кадрів прийшло від камери, середній час очікування (select), блокування і стиснення, а також скільки кадрів реально отримав клієнт і скільки часу зайняло очікування кадру та відправка. Приклад ручного запуску:
  `MJPG_STATS=1 mjpg_streamer -i "input_uvc.so -d /dev/video0 -r 320x240 -f 30 -y -n" -o "output_http.so -p 8090"` і `logread | grep stats`.
- У образ додано `mjpg-streamer-output-file` (для тестів без HTTP: `-o "output_file.so -f /tmp/pics -d 0"`).

## v7: рушій ustreamer, меню керування, меню трафіку
**Рушій.** За замовчуванням усі камери працюють через `ustreamer` 6.52 (`--format YUYV --encoder CPU --tcp-nodelay`, адреса `http://роутер:порт/stream`).
`mjpg-streamer` лишається в образі як запасний рушій; для меншого образу запустіть збірку з `engines = ustreamer-only`.
Пакет `packages/ustreamer` тепер ставить лише бінарник: власні init-скрипт, `/etc/config/ustreamer` і USB-hotplug з апстриму прибрано,
бо вони запускали б другий екземпляр на `/dev/video0:8080` поряд зі службою `cams`.

**Поворот 180°** у ustreamer не працює (потрібні апаратні керування камери, їх нема). Камера з поворотом 180° і рушієм «за замовчуванням»
автоматично працює через mjpg-streamer (рядок у `logread | grep cams` і примітка в таблиці потоків). Поворот у кодері ustreamer ще не реалізовано.

**Меню «Вебкамери» (керування).** Кнопки: Запустити / Зупинити / Перезапустити / Застосувати яскравість. Вкладки камери: «Потік», «Зображення», «Рушій».
На вкладці «Рушій»: вибір рушія для камери, якість JPEG, TCP_NODELAY, економія процесора без глядачів, `--exit-on-device-error`,
`--drop-same-frames`, буфери, потоки кодування. Яскравість/контраст для ustreamer ставляться через `v4l2-ctl` на ходу.

**Меню «Вебкамери: трафік» (інфо).** З'являється лише коли в «Вебкамери» -> «Загальне» увімкнено «Меню трафіку». Тоді ж ставляться nft-лічильники
(`table inet cams_stat`, по одному правилу на порт камери). Сторінка раз на 1/2/5/10 с запитує `/usr/sbin/cams-stats` і показує на кожному кроці:
1) камера: к/с з камери, 2) кодер: к/с на виході, 3) глядачі: кількість і к/с кожного, 4) мережа: кбіт/с, кБ на кадр, усього байтів.
Підказки пояснюють, де втрачаються кадри (камера/USB, кодер, мережа). Для mjpg-streamer доступні лише мережа й підключення.
Поки сторінка закрита, на роутері нічого не опитується.

## Порівняння рушіїв
`sh /usr/sbin/cams-ustest.sh /dev/video0 320x240` (потім `/dev/video2`). Скрипт зупиняє службу `cams`, мірить кадри за 10 с у ustreamer
(з `--tcp-nodelay` і без, 30 та 15 к/с) та в mjpg-streamer, і запускає службу назад.

## Файли на роутері
`cams-list` (формат: 24 поля, поля 16-24: рушій|якість|nodelay|slowdown|exit_on_error|drop_same|buffers|workers|примітка),
`cams-stats` (знімок статистики; `sync`/`teardown` керують лічильниками), `cams-apply`, `cams-check`, `cams-watchdog`, `cams-usbreset`.
